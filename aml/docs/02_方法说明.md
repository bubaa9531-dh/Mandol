## 一、系统简介

**Mandol-AML** 是课题组**自研**记忆系统 **Mandol**（An Agglomerative Agent Memory
System for Long-Term Conversations）为适配 AML 赛事而建立的参赛版本：

- 在赛事开发仓库（bubaa9531-dh/Mandol，fork 自主开发仓库以独立开发）上仅新增赛事适配层；
- 不修改 Mandol 主体：`src/mandol/`、`pyproject.toml`、`uv.lock` 等核心内容零改动；
- 按 Agent Memory Leaderboard（AML）现行接口规范实现 `Add`（记忆写入）与
  `Search`（记忆检索）两个同步 HTTP 接口；
- 参赛组别：开源方法榜（学术方法榜）；赛道：文本记忆赛道 + 代码记忆赛道。

## 三、本次改动说明（赛事适配，主体不变）

1. **新增** `src/mandol_aml/`（FastAPI 适配包）：AML 契约层（Add/Search/Health、
   字段校验与逐字回显、Memory System Key 鉴权、进程内限流、30 天数据留存清理、
   可选高层记忆开关）。
2. **记忆编排**（`memory.py`）：
   - 默认 `shared` 后端：进程内共享一张 Mandol 语义图，按 AML `user_id` 建立独立
     MemorySpace 检索隔离；`session_id` 仅作元数据（AML 契约中 session_id 不是检索边界）。
   - 可选 `isolated` 后端：每个 `user_id` 独立语义图（模型权重经 Mandol 模型管理器
     共享），用于开启 Mandol 混合检索（MultiRetriever）而不跨用户泄漏。
3. **Add**：将平台下发的消息块转为 Mandol `MemoryUnit`（正文存 `text_content`，
   role/timestamp/session/request 等存 metadata），经 `SemanticGraph.batch_add_units()`
   写入；写入完成、立即可检索后才返回 HTTP 200。
4. **Search**：默认 `SemanticGraph.search_similarity_in_graph()` 稠密检索并按用户空间
   限定，返回按相关度降序的记忆证据 `{id, content, score?, created_at?}`；
   只返回记忆，不生成答案。
5. **可选实验特性（默认关闭）**：`AML_HIGH_LEVEL_MEMORY=1` 时在后台调用
   `mandol.auto_builder.build_high_level_memory()` 做记忆组织（分层摘要/情景/实体），
   仅用于记忆整理，不参与答题、不接触评测问题答案。
6. **新增** Dockerfile / docker-compose / 环境模板 / 冒烟脚本 / 契约测试 / 文档
   （均在 `aml/`、`tests/` 等新增路径；完整清单见 CHANGES.md）。

## 四、运行环境

| 项 | 要求 |
| --- | --- |
| Python | 3.12（>=3.12,<3.13，Mandol 要求） |
| 依赖安装 | 仓库根目录 `uv sync --frozen --no-dev`（依赖由 pyproject.toml 声明） |
| Embedding 模型 | 默认 `Qwen/Qwen3-Embedding-0.6B`（可用 `BAAI/bge-m3`、`all-MiniLM-L6-v2`），首次运行自动下载 |
| LLM（仅可选高层记忆） | 按 env.template 配置 provider Key（DeepSeek/DashScope 等），部署端 `.env` 设置 |
| 建议实例 | 8 vCPU / 16–32 GB 内存起；稠密编码可用 GPU 加速（Dockerfile 支持 CPU 与 CUDA） |

## 五、启动与自测（与仓库 README 一致）

```bash
uv sync --frozen --no-dev
cp aml.env.example .env        # 配置 AML_MEMORY_SYSTEM_KEY 等
python -m mandol_aml            # 默认 0.0.0.0:8000
python aml/scripts/smoke_test.py --base-url http://127.0.0.1:8000
pytest tests/ -v
docker compose up -d --build    # 或容器化部署
```

## 六、赛道适配说明

- **文本记忆赛道**：写入长程多轮对话，检索支撑事实召回、多跳关联、时序、画像个性化、
  规则与安全类问题的证据召回。
- **代码记忆赛道**：将历史工程任务（调试过程、开发经验、项目上下文文本）写入记忆，
  后续检索可复用工程经验；检索链路与文本赛道一致。
- 同一套服务可服务两个赛道；报名时分别选择赛道并绑定同一版本即可。
