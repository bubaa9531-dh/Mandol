## 一、一句话简介

本系统 **Mandol-AML** 在 [Mandol](https://github.com/AgentCombo/Mandol)
（一个面向长期对话的分层聚合智能体记忆系统，论文
[arXiv:2606.29778](https://arxiv.org/abs/2606.29778)）之上，按赛事要求封装
`Add`（记忆写入）与 `Search`（记忆检索）两个标准化接口，不改动 Mandol 主体，
用于参加 AML 文本记忆与代码记忆赛道（开源方法榜）。

## 三、本次改动（封装层，不改主体）

1. 新增 `src/mandol_aml/`：FastAPI 实现的 AML 契约层（Add/Search/Health、
   请求/响应校验、Memory System Key 鉴权、限流、30 天数据留存清理）。
2. 新增记忆编排 `memory.py`：
   - 默认 `shared` 后端：进程内共享一张 Mandol 语义图，按 AML `user_id`
     建独立 `MemorySpace` 隔离；`session_id` 仅作元数据。
   - 可选 `isolated` 后端：每 `user_id` 独立语义图（模型权重经 Mandol 模型
     管理器共享），支持 Mandol `MultiRetriever` 混合检索，无跨用户泄漏。
3. `Add` 将消息块转为 `MemoryUnit` 后经 `SemanticGraph.batch_add_units()` 同步
   写入并立即可检索；`Search` 默认 `SemanticGraph.search_similarity_in_graph()`
   稠密检索，按用户空间限定，返回降序证据。
4. 可选实验特性（默认关闭，需自测后开启）：`AML_HIGH_LEVEL_MEMORY=1` 时后台调用
   `mandol.auto_builder.build_high_level_memory()` 构建分层/情景/实体高层记忆。
5. 新增 Dockerfile、docker-compose、运行脚本与文档；`src/mandol/`、
   `pyproject.toml`、`uv.lock` 等上游文件零改动（详见 `aml/CHANGES.md`）。

## 四、运行环境

| 项 | 要求 |
| --- | --- |
| Python | 3.12（>=3.12,<3.13，Mandol 要求） |
| 依赖 | 由上游 `pyproject.toml` 声明（torch 2.8.0、sentence-transformers、faiss-cpu、rocksdict、fastapi、pydantic 等），`uv sync --frozen --no-dev` 安装 |
| Embedding 模型 | 默认 `Qwen/Qwen3-Embedding-0.6B`（Mandol 论文同款轻量模型；可用 `BAAI/bge-m3` 等），首次运行自动下载 |
| LLM（仅可选高层记忆） | 需配置上游 env 模板中的 provider Key（如 `DEEPSEEK_API_KEY` 等） |
| 推荐实例 | 8 vCPU / 16–32 GB 内存（稠密检索 CPU 可跑；编码可用 GPU 加速） |

## 五、启动方式

本地：

```bash
uv sync --frozen --no-dev
cp aml.env.example .env   # 设置 AML_MEMORY_SYSTEM_KEY 等
python -m mandol_aml      # 监听 0.0.0.0:8000
```

Docker：

```bash
docker compose up -d --build
```

自测：

```bash
python aml/scripts/smoke_test.py --base-url http://127.0.0.1:8000
pytest tests/test_contract.py -v
```

## 六、面向两个赛道的适配说明

- **文本记忆赛道**：写入长程多轮对话（按 user/session 组织），检索支持事实召回、
  多跳关联、时序、画像与规则类问题所需证据；高层记忆选项可进一步提升多跳/时序召回。
- **代码记忆赛道**：把历史工程任务（调试过程、开发经验、项目上下文文本）作为记忆写入，
  后续按问题检索可复用的工程经验；检索链路与文本赛道一致，无需切换配置。
- 同一套 Add/Search 服务可同时服务于两个赛道；报名时分别选择赛道并绑定同一版本即可。
