## 2. 契约（与官网 API Guide 一致：https://agentmemoryleaderboard.ai/api-guide）

### Add 请求（示例）

```json
{
  "request_id": "eval:<run_id>:locomo_refined:conv-0:chunk-0",
  "messages": [
    {"role": "user", "timestamp": 1704067200000, "content": "raw memory text"}
  ],
  "user_id": "eval:<run_id>:locomo:conv-0",
  "session_id": "eval:<run_id>:sample:0"
}
```

字段：`request_id`（必填，响应须逐字回显）、`messages`（必填有序数组；`role`、`content` 非空，`timestamp` 可选 Unix 毫秒）、`user_id`（必填，检索隔离唯一边界）、`session_id`（必填，标识来源会话，仅作分组/元数据）。

### Add 响应（数据持久化且立即可检索后返回 HTTP 200）

```json
{"success": true, "request_id": "...", "user_id": "...", "session_id": "..."}
```

- `success` 必须为布尔 `true`；三个 ID 与请求逐字一致；
- 不支持 202 / 任务 ID / 轮询地址；响应无需 `memory_ids`。

### Search 请求（示例）

```json
{
  "query": "Which answer best matches the memory?",
  "options": ["A. ...", "B. ..."],
  "user_id": "eval:<run_id>:locomo:conv-0",
  "top_k": 100
}
```

字段：`query`（必填，原文检索，不替换为答案）、`options`（可选）、`user_id`（必填，与 Add 完全一致）、`top_k`（必填，返回数不得超过该值；正式外部评测为 100）。

### Search 响应（data 按相关度降序，数量 ≤ top_k；无结果返回空数组）

```json
{
  "data": [
    {"id": "mem_1", "content": "remembered fact text", "score": 0.87, "created_at": "2026-07-01T12:00:00Z"}
  ]
}
```

- `data` 为数组，不得用 `items` 包装或返回顶层数组；`id`、`content` 必填非空；
- `score`（越高越相关）、`created_at` 可选；其他未声明字段平台忽略；
- 只返回记忆证据，**不生成最终答案**、不把答案伪装成记忆。

## 3. 错误码与平台重试语义（实现已对齐）

| HTTP | 含义 | 平台行为 |
| --- | --- | --- |
| 400/422 | 契约/校验错误 | 不重试 |
| 401/403/404 | 鉴权失败/拒绝/路径错 | 不重试 |
| 408/425/429/500/502/503/504 | 瞬时不可用/限流/服务失败 | 有界重试（Search 的 409 不重试，Add 的 409 重试） |

- 业务错误体统一 `{"detail":{"reason":"..."}}`（已实现）；
- 本服务限流超限返回 429 + `Retry-After`。

## 4. 鉴权与凭证

- Memory System Key：由参赛方在部署端设置 `AML_MEMORY_SYSTEM_KEY`，支持 `Authorization: Bearer <key>`、`Authorization: Token <key>`、`X-Api-Key: <key>`。
- 未配置 Key 时端点开放——平台仅允许 Smoke 兼容性检查使用无鉴权端点，**正式评测前必须配置**。
- Eval/Leaderboard Key（平台签发）与 Memory System Key（参赛方签发）是两套凭证，均**不得**写入公开仓库、URL、截图或邮件正文。

## 5. 容量 / 超时 / 限流（提交时如实填写，须与部署一致）

| 项 | 申报值（默认） | 说明 |
| --- | --- | --- |
| Add 超时 | 60 s（`AML_ADD_TIMEOUT_SECONDS`） | 服务内为“目标处理时长”，建议在反向代理/网关按同值设硬超时（平台对 408/425/5xx 会重试） |
| Search 超时 | 30 s（`AML_SEARCH_TIMEOUT_SECONDS`） | 同上；稠密检索实测远低于该值 |
| 写入吞吐 | 单实例 ≥ 10 QPS（批量更高） | 与 embedding 硬件相关 |
| 检索吞吐 | 单实例 ≥ 10 QPS | Mandol 低延迟检索 |
| 限流 | 默认不限（`AML_RATE_LIMIT_RPM=0`） | 如设限须在报名表声明，超限返回 429 |
| 健康检查 | `/health` | 模型/服务未就绪返回 503，就绪返回 200 |
| 数据留存 | `AML_DATA_TTL_DAYS=30` | 评测数据于任务结束后 **30 天内**删除（系统自动清理 + 运维兜底） |

## 6. 数据、安全与隐私（合规要点）

- 检索隔离：`user_id` 为唯一隔离边界，绝不跨 `user_id` 检索；
- 日志：不记录消息正文，只记录 request_id / user_id（或其摘要）、状态、耗时与数量级；
- 评测数据仅用于完成当次任务：不训练、不微调、不重建数据集、不对外传播；
- 任务结束后删除评测数据：系统按 `AML_DATA_TTL_DAYS`（默认 30 天）自动清理；运维建议每次 Full 完成后手动重建/清库，最迟 30 天内完成；
- 运行说明：见仓库根目录 `README_AML_OVERLAY.md`、`aml/README.md`、Dockerfile 与 docker-compose.yml。
